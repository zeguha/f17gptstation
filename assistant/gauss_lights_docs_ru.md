# Управление умными лампочками Gauss (RU)

Этот документ описывает расширение ассистента детерминированным навыком управления светом.

## 1) Поддерживаемые команды

Покрыто базовым навыком:

- Включить/выключить: «включи свет», «в детской выключи»
- Яркость 0–100%: «приглуши до 30», «везде включи на 50%»
- Цветовая температура: «3000K», «сделай свет потеплее/похолоднее», «нейтральный»
- Цвет: «поставь синий», «цвет 255,0,0» (если лампа поддерживает RGB)
- Ночной режим: «ночной режим включи»
- Сценарии: «сценарий кино/чтение/сон» (в мок-адаптере демонстрационно)
- Комнаты: «в кухне …»
- «везде»: управление всеми лампами
- Запрос состояния: «как сейчас настроен свет в кухне?»

Намечено (как расширение поверх текущей абстракции):

- Группы (на уровне данных уже есть `Group`, надо добавить команды управления группами)
- Привязка/переименование голосом (можно добавить интенты `bind/rename`)

## 2) Архитектура

Слои:

1. NLU (детерминированный): [`assistant/intent_lights.py`](assistant/intent_lights.py:1)
   - интент/слоты (action + target + параметры)
   - терпимость к вариациям фраз
2. Менеджер устройств: [`assistant/lights_device_manager.py`](assistant/lights_device_manager.py:1)
   - обнаружение устройств (discover)
   - хранение ламп/групп/сцен в JSON
   - кэш состояния + pull-синхронизация (TTL)
3. Адаптер Gauss: [`assistant/lights_gauss_adapter.py`](assistant/lights_gauss_adapter.py:1)
   - интерфейс `GaussAdapter`
   - мок-реализация `GaussMockAdapter` для минимально рабочего примера
4. Оркестратор навыка: [`assistant/lights_skill.py`](assistant/lights_skill.py:1)
   - валидирует слоты, проверяет capabilities
   - выполняет команды с таймаутом
   - формирует короткие ответы для TTS
5. Хранилище: [`assistant/lights_store.py`](assistant/lights_store.py:1)
   - атомарная запись JSON состояния

### Авторизация

Зависит от варианта интеграции:

- LAN: локальный ключ/пейринг, хранить в `/.secrets/gauss.json` (не добавлено в код)
- Cloud: OAuth/токены, ротация/refresh
- HA/MQTT: токен Home Assistant или MQTT user/pass

### Ошибки/таймауты/повторы

В навыке установлен общий таймаут (`wait_for`). Повторы и backoff нужно реализовывать внутри адаптера (там лучше видно, что именно упало: сеть, 401, 5xx).

### Логирование/метрики

- логировать: распознанный интент, resolved targets, latency адаптера
- метрики: success/error/timeout, devices_online/offline

## 3) Спецификация интерфейсов (JSON)

### Модели

См. структуры данных:

- [`assistant/lights_types.py`](assistant/lights_types.py:1) — `Lamp`, `LampState`, `LampCapabilities`, `Group`, `Scene`

Пример `Lamp` (как в состоянии):

```json
{
  "id": "gauss-1",
  "name": "люстра",
  "room": "гостиная",
  "groups": ["основной"],
  "is_online": true,
  "capabilities": {
    "supports_brightness": true,
    "supports_ct": true,
    "supports_rgb": true,
    "supports_scenes": false,
    "supports_night_mode": true,
    "ct_min_k": 2700,
    "ct_max_k": 6500
  },
  "state": {
    "is_on": true,
    "brightness_percent": 50,
    "ct_kelvin": 3500,
    "color_rgb": [255, 255, 255],
    "color_mode": "ct",
    "night_mode": false,
    "scene": null,
    "updated_at": 1738690000.0
  }
}
```

### Интент (распарсенный)

См. [`assistant/intent_lights.py`](assistant/intent_lights.py:1) — `LightsIntent`.

Пример:

```json
{
  "action": "brightness_set",
  "target_scope": "all",
  "target_name": null,
  "brightness_percent": 50
}
```

### Команды адаптеру

Интерфейс: [`assistant/lights_gauss_adapter.py`](assistant/lights_gauss_adapter.py:1) — `GaussAdapter`.

Типичные команды:

- `set_power(lamp_id, on)`
- `set_brightness(lamp_id, percent)`
- `set_ct(lamp_id, kelvin)`
- `set_rgb(lamp_id, rgb)`
- `set_night_mode(lamp_id, on)`

### События

В текущем минимальном примере событий нет (pull-синхронизация по TTL).
Для реального адаптера рекомендуется добавить:

- `DeviceOnlineChanged(lamp_id, is_online)`
- `StateUpdated(lamp_id, state)`

## 4) Примеры диалогов

1) «Сделай свет потеплее в гостиной»
- intent: `ct_delta`, target=`room:гостиной`, delta=-350
- ответ: «Сделал свет теплее.»

2) «Везде включи на 50%»
- intent: `brightness_set`, target=`all`, brightness=50
- ответ: «Яркость 50%.»

3) «В детской выключи»
- intent: `power_off`, target=`room:детской`
- ответ: «Выключил свет.»

4) «Поставь синий в спальне»
- intent: `color_set`, target=`room:спальне`, color_name=синий
- если лампа без RGB: «Поставил цвет. (бра: цвет не поддерживается)»

5) «Как сейчас настроен свет в кухне?»
- intent: `state_query`, target=`room:кухне`
- ответ (пример): «кухня: включена, яркость 50%, 3500K.»

## 5) Крайние случаи

- Лампа офлайн: команда выполнится на остальных, в конце будет предупреждение `(<имя>: офлайн)`.
- Частичная поддержка функций:
  - нет RGB → `цвет не поддерживается`
  - нет CT → `температура не поддерживается`
- Конфликт: «выключи и на 50%» — пока решается приоритетом (яркость перехватывает «включи на 50»; сложные конфликты лучше решать диалогом).
- Неоднозначная комната/название: менеджер вернёт предупреждение, можно расширить уточняющим вопросом.
- Ограничения яркости: clamp 0..100.
- Ночной режим: включает свет и снижает яркость (в мок-адаптере).
- Отсутствие прав (cloud/HA): должно маппиться адаптером в доменную ошибку `AuthRequired` → «нет прав/нужно подключить».

## 6) Варианты интеграции Gauss (когда API неизвестен)

1) **LAN-протокол** (если лампы/хаб поддерживают локальное управление)
- Плюсы: работает без интернета, низкая задержка, приватность
- Минусы: иногда закрытый протокол/шифрование, сложнее discovery

2) **Облачный API производителя**
- Плюсы: проще документация/SDK (если есть), работает удалённо
- Минусы: зависит от сервиса, токены/лимиты, приватность

3) **Через Home Assistant / MQTT**
- Плюсы: зрелая экосистема, унификация устройств, готовые интеграции
- Минусы: нужен HA/MQTT брокер, чуть выше задержка

Абстракция адаптера позволяет заменить реализацию, не меняя NLU/skill/manager.

## 6.1) Реальные Gauss Wi‑Fi лампы через приложение WiZ (без хаба / без Home Assistant)

Если твои Gauss управляются приложением **WiZ**, самый простой путь без облака — включить LAN‑управление по протоколу WiZ (UDP 38899) и использовать адаптер `wiz_lan`.

### Шаги

1) **Проверь, что лампы и ассистент в одной Wi‑Fi сети** (один роутер, одна подсеть).
2) В приложении WiZ включи локальное управление, если оно есть:
   - обычно это что-то вроде *Settings → Integrations / Local network / Local control*.
3) Включи адаптер:
   - переменная окружения: `GAUSS_ADAPTER=wiz_lan`
4) (Опционально) Задай дефолтную цель для коротких команд:
   - `LIGHTS_DEFAULT_SCOPE=all` (или `room` + `LIGHTS_DEFAULT_ROOM=кухня`)
5) Запусти ассистента и скажи: «найди лампы».

### Если поиск ламп не работает (broadcast блокируется)

Иногда роутер или режим гостевой сети блокирует broadcast/UDP между клиентами (AP/client isolation). Тогда discovery не увидит лампы.

Фолбэк: **задай IP ламп вручную** (посмотри в роутере список DHCP‑клиентов):

```bash
export WIZ_IPS="192.168.1.10,192.168.1.11"
export GAUSS_ADAPTER=wiz_lan
```

### Если в приложении WiZ нет пункта «LAN / Local control»

Это не обязательно означает, что LAN протокол отсутствует. У части прошивок/регионов WiZ просто не показывает явный тумблер, но **локальные команды по UDP 38899 всё равно работают**.

Если же LAN реально отключён/урезан, то unicast-запросы `getSystemConfig/getPilot` не будут отвечать даже по известному IP.

### VPN и маршрутизация (важно)

Если на устройстве ассистента включён VPN (интерфейсы `utun*`), он может ломать broadcast/маршруты и давать ошибки вроде `No route to host`.
Решение: временно выключить VPN **или** задать корректный broadcast адрес явно:

```bash
export WIZ_BROADCAST_ADDR="192.168.1.255"
```

## 8) План тестирования

### Unit

- NLU: покрыть фразы → интенты/слоты (см. `test_intent_lights.py`)
- clamp/валидации: яркость, kelvin, rgb
- резолвинг целей: комнаты/везде/непонятно

### Integration

- skill + mock adapter: команда → изменение состояния → query_state
- офлайн: `is_online=False` → предупреждение
- частичные capabilities: RGB/CT отсутствуют

### Набор тестовых фраз (минимум)

- «включи свет»
- «выключи свет в детской»
- «везде включи на 50%»
- «приглуши до 30»
- «сделай ярче на 10% в кухне»
- «сделай свет потеплее»
- «поставь 3000K в спальне»
- «поставь синий»
- «цвет 255,0,0 в гостиной»
- «ночной режим включи в детской»
- «сценарий кино в гостиной»
- «как сейчас настроен свет в кухне?»

### Устойчивость и безопасность

- Rate limit: ограничить частоту команд на устройство
- Таймауты + повторы (адаптер)
- Валидация диапазонов (0..100, 2700..6500)
- Защита от инъекций/злонамеренного ввода в облачных запросах

python3 -m unittest discover -s assistant/tests -p "test_*.py" -q
